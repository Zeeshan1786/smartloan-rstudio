# SmartLoan

SmartLoan is an RStudio classroom project that compares **logistic regression**, a **decision tree**, and a **random forest** on the task of predicting a recorded loan approval label. All training, plots, and predictions run in R.

## Open the browser app

Open **SmartLoan.Rproj** in RStudio and source **RunWeb.R**, or run `Rscript RunWeb.R` from the project folder. Open [http://127.0.0.1:3840/](http://127.0.0.1:3840/) while that R session is running. A fresh GitHub checkout trains once to generate the local model, results, and plots. Run `SmartLoan.R` again and restart the app if you change the dataset or model settings.

The frontend in `web/frontend/` provides a form with all 11 applicant inputs, two sample profiles, a validation/test metrics switch, and an expandable chart gallery. Each prediction updates two charts: the applicant's score against the selected cutoff and a what-if comparison that changes only the credit history flag. These are model scores for an academic exercise, not a causal effect or a credit decision. The Plumber backend in `web/api.R` validates and scores one profile at a time with the saved R model. The app does not store submitted profiles.

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | Readiness, loaded model, and dataset. |
| `GET /api/project` | Example profiles, split sizes, model metrics, and chart names. |
| `POST /api/predict` | Accept all 11 documented fields as one JSON object. Use `null` for an unknown value. |

The server listens on loopback for the classroom demo. To use a different local port, set `SMARTLOAN_PORT` before launching it.

## Run the complete project

1. Extract the ZIP and open **SmartLoan.Rproj** in RStudio.
2. Open **SmartLoan.R** and click **Source**. The first run installs missing R packages (`ggplot2`, `rpart`, `ranger`); that step needs internet access. The included demo data can be used offline once the packages are installed.
3. Open **PROJECT_REPORT.md** for the methodology and measured results. The `plots/` directory contains exploratory charts, ROC curves, a metrics comparison, three confusion matrices, a decision tree, and forest feature importance.
4. To score new sample applicants, edit **data/example_applicants.csv** and source **PredictLoan.R**. This loads the saved model and writes **results/applicant_predictions.csv** without retraining.

From a terminal opened in this folder, the equivalent commands are:

```sh
Rscript SmartLoan.R
Rscript PredictLoan.R
```

## Dataset options

- **Runs immediately:** `data/demo_train.csv` contains 650 synthetic records generated by `data/make_demo_data.R`. The labels are fictional. The included outputs and report are from this dataset; its metrics are only evidence that the classroom pipeline works.
- **Use the assignment dataset:** The starter ZIP references [Kaggle Loan Eligibility Prediction](https://www.kaggle.com/competitions/loan-eligibility-prediction/data), which asks users to sign in and accept competition rules to access the data. [Analytics Vidhya's Loan Prediction practice problem](https://www.analyticsvidhya.com/datahack/contest/practice-problem-loan-prediction-iii/) is another source for a labelled dataset with this schema. Download the labelled CSV through the provider, place it in `data/` as `train.csv`, then source `SmartLoan.R` again. The script gives that file priority and regenerates the report and results. Cite the provider you actually used. The bundled demo should not be submitted as results from the original competition dataset.

## Required applicant parameters

All 11 predictor columns must be present in the CSV. A cell can be blank for an unknown value; the model uses the training median (numeric) or most common training category. If a column has no variation in the training split, it is omitted from the fitted model and listed in the report. Text values are matched without regard to case.

| CSV field | Accepted values and meaning |
|---|---|
| `Gender` | Female or Male, using the source schema categories. |
| `Married` | Yes or No. |
| `Dependents` | 0, 1, 2, or 3+; 3 is accepted as 3+. |
| `Education` | Graduate or Not Graduate. |
| `Self_Employed` | Yes or No. |
| `ApplicantIncome` | Finite number, 0 or higher, in the source income units. |
| `CoapplicantIncome` | Finite number, 0 or higher, in the same units; use 0 when there is no co-applicant income. |
| `LoanAmount` | Positive finite number in thousands, consistent with the referenced dataset. |
| `Loan_Amount_Term` | Positive whole number of months. |
| `Credit_History` | 0 or 1, a dataset flag for whether credit history meets the source criteria; not a credit score. |
| `Property_Area` | Rural, Semiurban, or Urban. |
| `Loan_Status` | Required only for training: Y (approved) or N (not approved); 1/0 also accepted. |
| `Loan_ID` | Optional identifier; never used to fit the model. |

## Model settings

Edit the `cfg` list at the top of `SmartLoan.R` to change the defaults.

| Setting | Default | Purpose |
|---|---:|---|
| `seed` | 123 | Reproducible split and forest fit. |
| `validation_fraction` | 0.14 | Approximate fraction of profile groups reserved for model selection. |
| `test_fraction` | 0.30 | Approximate fraction of profile groups kept for final evaluation. The rest train the models. |
| `threshold_grid` | 0.05 to 0.95, step 0.01 | Candidate score cutoffs. Each model's cutoff is selected on validation. |
| `tree_cp` | 0.01 | Decision tree complexity control. |
| `tree_minsplit` | 10 | Minimum observations needed to consider a decision tree split. |
| `forest_trees` | 300 | Number of trees in the random forest. |
| `forest_min_node` | 10 | Minimum node-size setting for the probability forest. |
| `forest_mtry` | NULL | Use ranger's default number of candidate features per split; set a number to override it. |

## Explain it to faculty

1. Show the input columns and explain that `Loan_Status` is the label the model learns to predict.
2. Show how duplicates are handled and why the same profile cannot cross splits. Medians and modes come from the training records only.
3. Explain the models: logistic regression is the baseline, a decision tree gives readable rules, and a random forest averages predictions from many trees.
4. Open `results/validation_metrics.csv` to see the cutoff and balanced accuracy for each model. Balanced accuracy averages recall and specificity, giving each class equal weight. It selects both the cutoff and the model using validation records only, with ROC AUC breaking ties between models. Open `results/model_performance_metrics.csv` for the fixed test benchmark.
5. Change an example applicant row and run `PredictLoan.R` to show that the saved model can score it.

This project predicts dataset labels for academic practice. Its outputs are not a lending recommendation, an assessment of creditworthiness, or evidence that demographic inputs should be used in real decisions.
